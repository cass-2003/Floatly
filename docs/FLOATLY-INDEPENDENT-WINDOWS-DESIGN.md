# Floatly 独立窗口设计方向：TodoList 与 Notes

> 更新时间：2026-06-18  
> 目标：整理 TodoList 与 Notes 两类独立弹窗/页面的产品边界、设计方向、数据模型影响和推荐落地顺序。  
> 结论：主桌面小组件保持轻量扫读，复杂管理能力进入独立玻璃窗口。

## 1. 总体判断

Floatly 主窗口的核心价值是桌面常驻、快速扫读和轻量操作，不适合承载完整任务管理或知识管理流程。TodoList 与 Notes 都应该作为独立窗口发展：

- 主桌面小组件：只显示最近、置顶、今日聚焦、快速记录和入口。
- TodoList 独立窗口：负责任务管理、筛选、状态、统计和详情。
- Notes 独立窗口：负责灵感收集、便签管理、分类标签、详情编辑和知识沉淀。

视觉上，两者都应延续 Floatly 的深色玻璃语言：深蓝黑背景、大圆角、弱边框、半透明卡片、蓝紫主按钮、少量橙色/绿色/黄色分类强调。不要把独立窗口做成传统后台管理系统，也不要把所有功能硬塞进主面板。

## 2. TodoList 方向

### 2.1 设计定位

TodoList 是 Floatly 的任务管理子系统。它适合独立窗口，不适合原封不动塞回主桌面小组件。

目标体验：

- 今日聚焦一眼可见。
- 新建、完成、星标、编辑、删除路径明确。
- 支持全部、今天、明天、本周、已完成等筛选。
- 任务卡片用轻量色条表达优先级，不使用大面积高饱和色块。
- 统计和空态服务扫读，不抢任务列表焦点。

### 2.2 已落地第一版

当前第一版 TodoList 独立窗口已经完成：

- 大圆角无原生标题栏玻璃窗口。
- 顶部标题、搜索、新建任务入口。
- `全部 / 今天 / 明天 / 本周 / 已完成` 分段筛选。
- 高/中/低优先级视觉分组。
- 当前最重要卡片。
- 任务统计卡片。
- 空态和底部快捷新建入口。
- 现有完成、星标、编辑、删除逻辑继续复用 `TodoStore`。

### 2.3 当前工程取舍

这版没有修改 TodoList 数据结构。当前仍使用旧字段：

- `Title`
- `Time`
- `Date`
- `DueDate`
- `Done`
- `Pinned`

因此当前高/中/低优先级只是展示推断：

- 星标任务或今日/逾期截止任务：高优先级。
- 今天或明天任务：中优先级。
- 其余未完成任务：低优先级。

这不是最终任务模型。后续若继续完善 TodoList，应先扩展数据结构，再补全 UI。

### 2.4 后续数据模型建议

后续可以考虑为 `TodoItem` 增加：

- `Priority`：`High / Medium / Low`
- `Status`：`Todo / InProgress / Done / Overdue`
- `Tags`
- `Notes`
- `Subtasks`
- `CreatedAt`
- `UpdatedAt`
- `CompletedAt`

数据迁移要保持旧数据可读，不能让现有待办丢失或全部被错误归类。

### 2.5 后续功能建议

推荐后续迭代：

1. 真实优先级与任务状态。
2. 标签和分类。
3. 任务详情页。
4. 子任务。
5. 过期/今天/本周等更准确的时间分组。
6. 任务统计和完成趋势。

## 3. Notes 方向

### 3.1 设计定位

Notes 更适合作为 Floatly 的知识和灵感收集子系统。相比 TodoList，Notes 更依赖数据模型，不能只做 UI。

目标体验：

- 快速记录灵感。
- 管理最近、收藏、分类、标签和草稿。
- 卡片网格适合扫读便签内容。
- 右侧详情预览适合快速阅读和轻量编辑。
- 支持模板化创建，如空白便签、待办清单、会议记录、读书笔记、项目计划。

第二张 Notes 设计图更适合作为主目标稿：它是完整产品界面，而不是功能展示拼图。上一张图可以作为模块状态和局部能力参考。

### 3.2 主目标结构

Notes 独立窗口建议采用：

- 左侧导航：全部便签、最近使用、收藏、分类、标签、归档、回收站。
- 顶部区域：问候语、搜索、视图切换、排序。
- 分类统计卡片：全部、想法、工作、学习、草稿、自定义分类。
- 中间区域：便签卡片网格或列表。
- 右侧区域：便签详情预览。
- 快速记录：短输入、保存便签、标签入口。
- 模板选择：空白便签、待办清单、思维导图、会议记录、读书笔记、项目计划。
- 窄窗口/移动式布局：底部导航 + 单列列表 + 浮动新增按钮。

### 3.3 Notes 需要先改数据

当前便签如果只依赖简单文本字段，就不足以支撑设计图中的分类、收藏、详情、模板和导出能力。建议先扩展 `ScratchNote`，再做完整 UI。

建议字段：

- `Title`
- `Content`
- `Category`
- `Tags`
- `Favorite`
- `Archived`
- `Deleted`
- `TemplateType`
- `CreatedAt`
- `UpdatedAt`

可运行时计算：

- `WordCount`
- `Preview`
- `LastEditedLabel`

可后续扩展：

- `Markdown`
- `Attachments`
- `LinkedNoteIds`
- `AiSummary`
- `SyncState`

### 3.4 Notes 高级能力边界

设计图中的以下能力不是纯 UI，需要真实功能支持：

- AI 智能总结。
- 语音输入。
- 多种模板。
- 知识关联。
- 云端同步。
- 导出 Markdown/PDF。

这些能力不应做成假按钮。可以先显示为后续规划，或隐藏到真实能力完成之后再上线。

## 4. 主面板与独立窗口边界

### 4.1 主面板保留轻量入口

主桌面小组件只保留：

- 今日待办前几条。
- 当前最重要任务。
- 最近便签或置顶便签。
- 快速记录入口。
- 打开完整窗口入口。

主面板不做完整列表管理、复杂筛选、富文本编辑、AI 设置或导出流程。

### 4.2 独立窗口承载复杂能力

TodoList 独立窗口承载：

- 筛选。
- 分组。
- 任务详情。
- 统计。
- 子任务。
- 批量管理。

Notes 独立窗口承载：

- 分类。
- 标签。
- 收藏。
- 模板。
- 编辑器。
- 导出。
- 归档和回收站。

## 5. 推荐落地顺序

### 阶段 A：TodoList 收尾

1. 补真实优先级和状态字段。
2. 增加任务详情页。
3. 把当前视觉分组从推断改为真实字段。
4. 做截图验收和交互复测。

### 阶段 B：Notes 数据模型

1. 扩展 `ScratchNote` 字段。
2. 写旧数据迁移规则。
3. 保证旧便签仍能正常显示、编辑和删除。
4. 增加分类、标签、收藏、归档、回收站的存取方法。

### 阶段 C：Notes 独立窗口第一版

1. 三栏窗口结构。
2. 搜索、分类和卡片网格。
3. 详情预览。
4. 快速记录。
5. 新建便签模板入口。

### 阶段 D：Notes 高级能力

1. Markdown 或富文本编辑。
2. 导出 Markdown/PDF。
3. AI 总结。
4. 语音输入。
5. 知识关联。
6. 云同步。

## 6. 设计验收原则

- 独立窗口可以比主面板信息密度更高，但仍要保持 Floatly 的安静、半透明和扫读感。
- 不增加额外实心背板，不使用方向性偏光或扫光。
- 深色主题不是纯黑后台，而是低眩光深蓝玻璃。
- 分类色只做小面积提示，不做大面积彩色卡片。
- 任何高级能力都必须有真实功能支撑，不能只有 UI 按钮。
- 主面板永远优先轻量，复杂工作流进入独立窗口。
